# Mail Management
# Сервис Управления Клиентами и Сообщениями

## Описание

Этот проект представляет собой веб-приложение для управления клиентами и сообщениями-рассылками. 
Пользователи могут добавлять, просматривать, редактировать и удалять получателей рассылок (клиентов)
и сообщения. А также Менеджеры наделены правами, для управления(отключения) рассылок.
Проект также включает REST API на Django REST Framework (DRF) для работы с ключевыми сущностями системы.
Реализованы API-эндпоинты для клиентов, продуктов, категорий и рассылок.

Также в проекте реализованы два способа отправки писем: через SMTP и через Email API (Resend, Brevo). 
Это позволяет использовать как классическую отправку через почтовый сервер, так и современный подход через внешние сервисы,
а также генерация Excel-файлов по выбранным продуктам для последующего использования в сообщениях и рассылках.

Проект демонстрирует разработку backend-системы для автоматизации рассылок с генерацией коммерческих предложений и интеграцией с внешними email-сервисами.
Проект включает покрытие ключевой бизнес-логики unit-тестами с использованием pytest и mock.

## Особенности деплоя

Проект задеплоен на Render (free-тариф).

- Сервис может “засыпать” при отсутствии активности (~15 минут)
- Первый запрос после простоя может выполняться 30–60 секунд (прогрев)

Фоновая обработка:

- Локально используется Celery + Redis для асинхронной отправки рассылок
- В production (Render free-tier) реализован fallback:
  отправка выполняется синхронно без Celery worker

Это позволяет сохранить работоспособность рассылок в условиях ограничений бесплатного хостинга.

### CI (Continuous Integration)

В проекте настроен CI с использованием GitHub Actions.

При каждом `push` и `pull request` автоматически выполняется:

- запуск unit-тестов (pytest)
- проверка кода линтером (flake8)
- проверка форматирования (black --check)
- запуск в изолированном окружении с PostgreSQL

Это позволяет гарантировать стабильность кода и предотвращает попадание ошибок в основной код проекта.


## Быстрый тест функционала

1. Зарегистрируйтесь в системе
2. Создайте клиентов (email должен совпадать с разрешённым в Resend)
3. Создайте сообщение
4. Сформируйте Excel-файл из продуктов
5. Перейдите в раздел "Мои предложения" и убедитесь, что файл сохранён
6. При необходимости удалите файл или прикрепите его к сообщению
7. Создайте рассылку и отправьте


Примечание:
На бесплатном тарифе Resend письма отправляются только на подтверждённый email.


## Функционал

### 1. Управление клиентами

- Добавление клиента: Пользователи могут добавлять новых клиентов, заполняя форму.
- Просмотр клиентов: Все клиенты отображаются в виде списка, где можно увидеть информацию о каждом клиенте.
- Редактирование : Пользователи могут редактировать информацию о клиенте.
- Удаление клиента: Пользователи могут удалить клиента из системы.


### 2. Управление сообщениями

- Добавление сообщения: Пользователи могут создавать новые сообщения, заполняя форму.
- Просмотр сообщений: Все сообщения отображаются в виде списка, где можно увидеть заголовок каждого сообщения.
- Редактирование сообщения: Пользователи могут редактировать содержание сообщений.
- Удаление сообщения: Пользователи могут удалять сообщения.
- Прикрепление сгенерированного файла: Пользователь может выбрать ранее сформированный Excel-файл и привязать его к сообщению.


### 3. Управление рассылками

- Создание рассылки: Пользователи могут создавать новые рассылки, выбирая получателей и сообщение.
- Отключение рассылки: Менеджеры могут отключать рассылки.
- Просмотр рассылок: Все рассылки отображаются в виде списка, где можно увидеть статус каждой рассылки.


### 4. Управление пользователями

- Регистрация пользователей: Новые пользователи могут зарегистрироваться в системе.
- Аутентификация: Пользователи могут входить в систему с использованием электронной почты и пароля.
- Профиль пользователя: Пользователи могут просматривать и редактировать свои профили.
- Блокировка пользователей: Менеджеры могут блокировать или разблокировать пользователей.

### 5. REST API (Django REST Framework)

Проект включает REST API для работы с основными сущностями системы.

Реализованы эндпоинты для:

- Клиентов (`/api/clients/`)
- Продуктов (`/api/products/`)
- Категорий (`/api/categories/`)
- Рассылок (`/api/mailings/`)

В API реализовано:

- CRUD-операции для основных сущностей
- Аутентификация пользователей
- Ограничение доступа к данным
- Разделение прав доступа для обычного пользователя и менеджера
- Фильтрация продуктов по категории

Для клиентов и рассылок реализована логика доступа:
- обычный пользователь видит только свои объекты
- менеджер может видеть все объекты
- Пользователь видит только свои сгенерированные файлы и может управлять ими (просмотр, удаление).

### 6. Генерация файлов и Email API

- Генерация Excel-файла по выбранным продуктам с указанием количества и цены.
- Сохранение сформированного файла в системе.
- Привязка сформированного файла к сообщению.
- Интеграция с Email API для отправки писем через внешний сервис.
- Подготовлена логика для отправки сообщений с вложениями.
- Просмотр списка сформированных файлов в личном кабинете (страница "Мои предложения").
- Удаление ранее сгенерированных файлов пользователем.


### 7. Фоновая отправка
- Фоновая отправка рассылок через Celery.
- Использование Redis в качестве брокера очередей для обработки задач.
- Поддерживаются два режима отправки рассылок:
- асинхронный режим через Celery + Redis
- синхронный режим как fallback для окружений без фонового worker

Celery и Redis используются для фоновой обработки задач локально. 
Для production/free-hosting предусмотрен fallback на синхронную отправку без Celery worker.

### 8. Redis используется как брокер очередей для Celery.

### Установка

1. Клонируйте репозиторий:
   `git clone https://github.com/kseniya161-max/Mail_Management.git`
2. poetry install
3. poetry shell
4. python manage.py migrate
5. python manage.py runserver
6. Для локальной асинхронной отправки писем используются Celery и Redis.
Пример переменной окружения:
- `USE_CELERY=True` — локальный асинхронный режим
- `USE_CELERY=False` — синхронный fallback-режим
7. Запуск Redis:
   `redis-server`
8. Запуск Celery worker:
   `celery -A config worker --loglevel=info --pool=solo`

9. Для работы Email API необходимо добавить переменные окружения:

- `RESEND_API_KEY`
- `RESEND_FROM_EMAIL`

Дополнительно тестировалась интеграция с Brevo API.

### Тестирование

В проекте реализованы unit-тесты для ключевой бизнес-логики.

Используется стек:
- pytest
- pytest-django
- unittest.mock (patch)

Покрыты тестами:
- генерация Excel-файлов (file_service)
- отправка рассылок (mailing_service)

Особенности тестирования:

- Используется `@pytest.mark.django_db` для работы с базой данных
- Внешние email API (Resend, Brevo) замоканы через `mock`, что позволяет:
  - не выполнять реальные HTTP-запросы
  - изолировать тесты
  - проверять корректность вызовов

- Проверяются:
  - создание записей в базе данных (MailingAttempt, EmailStatistics)
  - корректность логики отправки
  - обработка успешных и ошибочных сценариев

Пример запуска тестов:

```bash
pytest
```
6. После запуска приложение доступно по адресу:
- Веб-интерфейс: `http://127.0.0.1:8000/`
- API root: `http://127.0.0.1:8000/api/`
- DRF login: `http://127.0.0.1:8000/api-auth/login/`
